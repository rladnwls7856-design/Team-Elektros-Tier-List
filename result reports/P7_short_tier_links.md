# P7 — 짧은 티어 링크 `#t=` · 역할 공식 7종 고정

> 2026-10-07 · 브랜치 `feature/short-tier-links` · 테스트 **394개** 통과 · 브라우저 확인
> 리뷰: 2관점(저장 로직·화면 연결) 병렬 리뷰, 각 발견을 재현으로 확인. **확인 8건 + 사소 2건, 전부 수정**(테스트 8개 추가).

## A. 무엇을 · 왜

| 요청 | 한 일 |
|---|---|
| "16진수로 브롤러마다 코드, 0부터" | 코드 = **공식 API id − 16000000** (`00`=Shelly … `6e`=Vince). 새 브롤러는 API 가 다음 번호를 주므로 우리가 표를 관리할 필요가 없다 |
| "순서대로 나열하면 순서를 따로 기록할 필요 없다" | 티어별로 코드를 **카드 순서대로** 이어 붙인다. 순서 = 나열 순서 |
| "노트는 제외" | 링크에 노트 없음 (Export 파일에는 그대로) |
| "역할 목록 포함하지 말고" + "role 은 포함, Manage Role 은 기능 자체를 없애" | 역할 = **공식 클래스 7종 고정** → 목록을 보낼 필요가 없다. 링크에는 **클래스와 다르게 바꾼 브롤러만** `코드+마스크` 로 |
| "누락된 브롤러는 …" | 링크에 없는 브롤러(예: 보낸 사람의 목록이 옛날 것)는 **B 티어 맨 뒤**, 받는 사람이 쓰던 순서 그대로 |

**링크 해부** (`#t=20200g01g0agg04r0242`)

```
#t=  2   0200  g  01  g  0a  g    g  04   r  02 42
     │   S티어    A티어   B티어  C   D티어  역할: Bull(02) = Tank|Support (0x42)
     └ 코드 폭(16진 자리 수). 브롤러가 256명을 넘으면 3 으로 자동 증가
```

- 역할 마스크: 비트 i = `CLASS_ORDER[i]` (Damage Dealer=1, Tank=2, Assassin=4, Marksman=8, Artillery=16, Controller=32, Support=64). `00` = 역할 없음.
- **실측: 108명 보드 1,892자(P6 `#z=`) → 약 226자**(주소 제외). 압축 없이 이미 짧아서 `CompressionStream` 도 필요 없다 → 동기 함수.

**역할 정리 규칙 (`ensureClassRoles`)**
- 역할 목록은 항상 7종. 사용자가 만든 역할은 사라진다(Manage roles 삭제의 결과).
- 브롤러에게 붙은 클래스 역할은 유지(대소문자 정규화). 사용자 역할만 있던 브롤러는 자기 클래스로 돌아간다. 일부러 다 끈 브롤러(`[]`)는 그대로.

## C. Critical Path

### C-1. 링크는 브롤러 목록(roster)이 있어야 읽힌다
코드는 이름이 아니라 id 다. 그래서
- **보낼 때**: roster 가 없으면(첫 실행 + 오프라인) 링크를 못 만든다 → 토스트로 안내.
- **받을 때**: 부팅이 API 를 시도한 뒤(`rosterReady`)에 링크를 연다. 캐시만 있으면 캐시로 읽고, 캐시에 없는 새 브롤러 코드는 "모르는 코드"로 세어 건너뛴다.
- 브롤러 캐시(`team-brawl-v2:roster`)는 원래 `id` 를 저장하고 있었다 → 오프라인에서도 동작.

### C-2. 링크는 신뢰할 수 없는 입력
`decodeTierLink` 가 경계다: 길이 상한(8192자) → 정규식 하나로 구조 검사 → 길이가 폭의 배수인지 → 마스크 ≤ 0x7f. 어긋나면 throw 대신 `{ok:false}` 와 "링크가 손상되었습니다" 안내. 적용은 항상 **사본**에 하고, 확인 창 → `replaceBoard`(백업 → 저장 실패 시 되돌림) 순서를 그대로 탄다.

### C-3. 예전 링크
`#z=`(P6) · `#data=`(P2) 링크는 계속 열린다(노트·역할 포함 형식 그대로). 새로 **만드는** 링크만 `#t=`.

### C-4. 자산 버전
`?v=20261007.3` 으로 올렸다. 배포할 때마다 올린다(P6 C-1).

### C-5. 리뷰에서 고친 것
| 발견 | 고침 |
|---|---|
| 받는 쪽 목록에 클래스 정보가 없으면 링크 적용이 `[]`(=일부러 비움)을 써서 클래스가 영영 안 채워짐 | 클래스를 모르면 항목을 지움 → 나중에 `ensureClassRoles` 가 채움. 클래스 없는 브롤러를 일부러 비운 경우만 `00` 으로 보냄 |
| 이름이 `__proto__` 인 브롤러가 객체의 프로토타입을 바꿈 | 코드 계산에서 제외 |
| id 하나가 너무 크면(6자리 초과) 링크 전체가 깨짐 | 그 브롤러만 건너뜀 (`MAX_BRAWLER_CODE`) |
| 같은 id 를 가진 두 이름 → 같은 코드가 두 번 | 코드당 한 번만 |
| 역할 부분에 같은 코드가 두 번이면 마지막이 이김(티어는 처음이 이김) | 처음이 이김으로 통일 |
| 부팅 중 오류가 나면 링크가 영원히 대기 | `try/finally` 로 반드시 진행 |
| 오프라인 안내 "새로고침하세요" — 주소에서 링크가 이미 지워져 효과 없음 | "링크를 다시 여세요" |
| 목록 로딩 중 링크를 두 번 열면 확인 창 2번 + Undo 가 첫 링크 보드로 | 대기 링크는 하나(마지막 것) + "불러오는 중" 안내 |
| 아는 브롤러가 하나도 없는 링크도 "열까요?"를 물음(전원 B 로) | 열지 않고 안내 |

## D. 새로 도입한 것

| 무엇 | 설명 |
|---|---|
| `encodeTierLink` / `decodeTierLink` / `applyTierLink` | `#t=` 링크 만들기 · 구조 검사 · 받는 보드 사본에 적용 (`{state, listed, unknown, missing}`) |
| `ensureClassRoles` | 역할을 공식 7종으로 고정 (부팅 · 가져오기 · Undo 때마다) |
| 비트마스크 (bitmask) | 여러 켜고 끄기를 숫자 하나에: 역할 7개 → 7비트 → 16진 2자리 |
| `rosterReady` (Promise) | "API 를 한 번 시도했다"를 기다리는 신호. 링크 처리를 그 뒤로 미룬다 |
